# Свободное место каталога

Сервер сайта каждый час проверяет файловые системы, содержащие фотографии и резервные копии. Для хостинга сборщика он выполняет `df -Pk` через существующее прямое SSH-подключение `hosting`. Компьютер владельца в проверке не участвует.

| Где | Что измеряется |
|---|---|
| Сайт | `/opt/avtopodborimport/photos` и `/var/backups/avtopodbor-catalog` |
| Сборщик | `~/che168/data` и `~/avto-private-backups/postgres` |

Пути на общем разделе дают одну строку. Замер использует поле Available, то есть место, доступное процессам. На общем хостинге показатель относится к файловой системе. Индивидуальную квоту нужно смотреть в панели провайдера, если она установлена.

Если свободно **строго меньше 3 ГиБ**, проверка пишет предупреждение в журнал systemd. Все проблемные разделы попадают в одно сообщение. Для Telegram используется `notify.py` и та же настройка, что у импорта, описанная в [правилах оповещения](sold-listings.md). Пока бот отложен владельцем, продолжает работать журнал. После настройки бота перезапуск таймера не нужен. Между попытками отправки выдерживаются полные 24 часа, в том числе при перезагрузке или ошибке доставки. Отметка хранится в `/var/lib/avtopodbor-disk-space/last-attempt` и защищена файловым замком. Отсутствие настроек бота не расходует суточный интервал.

Если хост или путь недоступен, служба отмечает неполную проверку, сохраняет показания доступных разделов и возвращает ненулевой код. На следующий час таймер повторит проверку.

## Установка на сервере сайта

Из каталога проверенной версии репозитория от root выполнить

```sh
install -m 644 scripts/notify.py scripts/check_disk_space.py /opt/avtopodborimport/
install -m 644 scripts/deploy/avto-disk-space.{service,timer} /etc/systemd/system/
systemctl daemon-reload
systemctl enable --now avto-disk-space.timer
systemctl start avto-disk-space.service
systemctl list-timers avto-disk-space.timer
journalctl -u avto-disk-space.service --since today
```

## Прогноз на 17–31 декабря 2026 года

Основа расчёта — снимок PostgreSQL и проверка файлов на сайте 27 ноября в 19:22 по Праге (21:22 МСК). В базе 46 383 активных машины. На разделе сайта свободно 5,03 ГиБ. На общем разделе сборщика свободно около 637 ГиБ. Загрузчик сохраняет два кадра. Наличие каждого кадра проверено на диске, для отсутствующих учтены доступные исходные ссылки. Использован средний занятый объём по файловым блокам отдельно для каждого кадра, 58,3 КиБ для первого и 59,9 КиБ для второго.

Весь январь 2024 допускается 17 декабря, когда расчётная дата растаможки достигает 31 января 2027 года. Уже 18 декабря расчётная дата — 1 февраля 2027 года и машины февраля 2022 года выходят из окна. До 31 декабря следующей смены регистрационного месяца нет. Более ранняя продажа части этих машин уменьшит декабрьское освобождение, поскольку их фото тогда будут удалены раньше. Удаление строк PostgreSQL обычно отдаёт место для повторного использования самой базе, поэтому возврат диска рассчитан только по файлам фотографий с одной жёсткой ссылкой.

При семи копиях и догрузке только январской группы на текущем парке получится около **4,46 ГиБ** свободно к 17 декабря и **4,57 ГиБ** после возрастной очистки. Если к 31 декабря загрузчик выберет все доступные два кадра вообще у всех остающихся машин, свободно будет **около 3,88 ГиБ**. В этот сценарий входят январь и остальные машины 2024 года; строки таблицы для этих групп не суммируются. Пока пишется новая копия, нужно дополнительное место под промежуточные файлы (сегодня на сайте примерно 138 МиБ для обоих архивов). Оценка не задаёт квоту и не учитывает рост Docker, журналов, базы и кэша или новые объявления и снятия с продажи. Каждая тысяча дополнительных оставшихся машин с двумя фотографиями уменьшает запас примерно ещё на 115 МиБ. Репрезентативной истории притока 2024 года пока нет: сбор нового возрастного диапазона начался 26 ноября.
