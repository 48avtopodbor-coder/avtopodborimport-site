# Прямой обмен между серверами

Восстановлен по просьбе владельца 23 ноября 2026 года. Работающий ПК для передачи
базы и фотографий не нужен. Действующие ключи и проверка подлинности SSH сохранены;
новые порты и туннели не создавались.

```text
Сервер сайта -- SSH / trigger.sh --> сборщик Che168 (каждый час в :10)
Сборщик -- проверенный SQLite-снимок по SSH --> сервер сайта (04:05)
Сервер сайта -- импорт снимка --> PostgreSQL --> каталог
Сборщик -- исходные фото по SSH --> кэш и /photos на сервере сайта --> посетитель
```

## Настройка

- На сервере сайта `/srv/che168/trigger.sh` использует прямой SSH-алиас `hosting`.
  Исходник: `scripts/deploy/trigger_collector.sh`. Запуск проверяется по изменению
  журнала сборщика через 20 секунд. `run_hourly.sh` на сборщике сохраняет свою
  прежнюю логику запуска и защиты от параллельных обходов.
- `/srv/che168/pull_db.sh` создаёт согласованный снимок на сборщике, передаёт его
  напрямую, проверяет SQLite, атомарно заменяет опубликованную копию и запускает
  импорт именно этой копии. Предыдущая копия сохраняется. Почасовой импорт в :20
  остаётся повторной попыткой, а не отдельной загрузкой снимка.
- `avto-photo-relay.service` получает ещё не сохранённые фотографии напрямую через
  сборщик. `avto-photo-batch.timer` каждые два часа пополняет первые три фото.
  Лимит размера и дополнительное сжатие не добавлены; резерв диска 4 GiB сохранён.
- `/srv/che168/pc-bridge/disabled` принудительно отключает временный режим: ни
  свежий heartbeat, ни случайный запуск старого клиента не переводят сайт обратно
  на ожидание ПК. Фото-клиент не получает новых заданий.
- На ПК `avto-pc-bridge.service` остановлен и отключён от автозапуска. Его файлы и
  существующие изображения сохранены для возможного явного возврата владельцем.
- Автоматизация Codex `automation-2` больше не переносит снимок через ПК и не
  включает мост. Она проверяет серверный импорт и выполняет отдельную обработку
  переводов. Серверные словари и очередь неизвестных значений продолжают работать.

## Проверка

Проверять `pull.log`, `import.log`, `trigger.log`, журнал `avto-photo-relay.service`
и `avto-photo-batch.service`. На ПК сервис должен быть `inactive` и `disabled`.
Наличие флага прямого режима должно давать `workstation_alive() == False`, а
`pc_bridge_server.work()` — пустой список с причиной `direct server mode`.

Проверка после переключения включает прямой запуск сборщика, перенос и проверку
снимка, импорт, получение отсутствовавшего в кэше фото и малую партию загрузчика.
Эти задания запускаются на сервере через systemd и продолжаются после отключения
управляющего SSH-соединения.

Контрольный прогон 23 ноября: запуск сборщика подтверждён журналом; SQLite-снимок
содержит 70 008 машин, `quick_check` — `ok`. Импорт завершился за 34 секунды,
активных автомобилей с ценой — 44 038. Небольшая партия передала напрямую 30 фото
за 36 секунд, без ошибок и отказов источника. Отдельное отсутствовавшее в кэше фото
успешно получено через relay и сохранено на сервере сайта (HTTP 200, WebP).

Резервные копии заменённых скриптов на сервере:
`/opt/avtopodborimport/config-backups/direct-20261123T132729Z`.
Возврат к временному режиму требует отдельного решения владельца: вернуть wrapper
запуска, убрать флаг `disabled`, включить сервис ПК и изменить автоматизацию.
