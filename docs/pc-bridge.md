# Временный канал через компьютер

Компьютер подключается к сборщику и серверу сайта двумя шифрованными SSH-соединениями. Фотографии проходят через ПК без изменения разрешения и сжатия. Они сохраняются на сервере сайта; посетители получают их с сайта. На ПК временно хранится только текущая партия, после передачи временный файл удаляется.

## Установленная схема

- `avto-pc-bridge.service` — пользовательский сервис systemd на рабочем компьютере. Автоматически запускается при входе в систему, повторяет работу после ошибок. Установленная программа находится в `~/.local/share/avto-pc-bridge`, отдельно от Git worktree. Ей нужны только Python и OpenSSH.
- SSH-конфигурация и существующий ключ доступа к сборщику находятся в `~/.config/avto-pc-bridge` (папка 700, файлы 600). Проверка ключей серверов включена. Пароли и ключи не входят в репозиторий. Соединения переиспользуются через ControlMaster.
- На сервере сайта `pc_bridge_server.py` выдаёт задания и принимает проверенные tar-пакеты только через существующий SSH-доступ. Дополнительные публичные порты не открываются.
- При запросе ещё не сохранённого фото `photo_relay.py` добавляет URL в `/srv/che168/pc-bridge/pending`. Если компьютер недавно обращался к очереди, веб-запрос ждёт копию в локальном кэше до 45 секунд.
- Компьютер сначала передаёт запрошенные посетителями снимки, затем главные фотографии всех машин, вторые и третьи. Одно соединение со сборщиком скачивает партию из 12 снимков последовательно с паузой. Отказы источника вызывают паузу, отсутствующие файлы откладываются на 24 часа. Сохранение останавливается при остатке менее 4 GiB.
- Пути `local_photo`, `local_photo_2`, `local_photo_3` записываются только после появления настоящего изображения. Кэш и публичная копия используют жёсткие ссылки на одном диске, без удвоения занимаемого места.
- Пока ПК обслуживает очередь, прямой фоновый загрузчик пропускает свой запуск. После выключения ПК отметка активности истекает через две минуты и остаётся прежний прямой путь между серверами. Сохранённые файлы продолжают открываться.

## Копия базы и переводы

Существующая автоматизация Codex на 08:30 по времени приложения дополнена первым шагом:

```bash
python3 ~/.local/share/avto-pc-bridge/pc_bridge_client.py --config ~/.config/avto-pc-bridge/ssh_config --state-dir ~/.cache/avto-pc-bridge --snapshot --refresh-snapshot
```

Сборщик создаёт согласованный SQLite-снимок, компьютер передаёт поток серверу сайта. Сервер сохраняет его во временный файл, выполняет `PRAGMA quick_check`, проверяет таблицы и непустую базу, атомарно заменяет опубликованный снимок, сохраняя предыдущий. Затем запускаются существующие импорт и словарь. Неполная передача не заменяет действующую копию. После успешного импорта автоматизация продолжает общий цикл переводов. Для этой задачи Codex и компьютер должны быть включены; фото-сервис работает независимо от открытого окна Codex, пока пользовательская сессия и сеть доступны.

## Проверка и остановка

```bash
systemctl --user status avto-pc-bridge.service
journalctl --user -u avto-pc-bridge.service -n 20
systemctl --user stop avto-pc-bridge.service
```

Остановка фото-сервиса не меняет данные и не удаляет изображения. Для полного возврата к прямому режиму следует также убрать шаг копирования через ПК из автоматизации Codex. Обычные задания серверов сохранены.
