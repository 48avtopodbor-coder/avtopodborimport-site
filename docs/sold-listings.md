# Удаление снятых с продажи автомобилей

По решению владельца снятые объявления и их фото больше не храним на сайте.
Основание — явное `is_active=0` в проверенной копии базы сборщика. Отсутствие
строки, таймаут, ошибка сети, пустая цена или неизвестный статус не означают продажу.

При импорте копируются только активные записи. Для подтверждённых неактивных ID
в одной транзакции создаётся очередь `sold_car_cleanup` и удаляются строки `cars`.
Повторный импорт не возвращает их. Сборщик сохраняет исходную отметку снятия;
если источник действительно выставит объявление снова, активная запись может
вернуться обычным импортом.

`avto-sold-cleanup.timer` каждые 15 минут повторяет очистку файлов сайта. Этот же
шаг выполняется после успешного ночного импорта. Очистка согласована с блокировками
импорта и загрузчика: во время партии переносится на следующую попытку. Удаляются
локальные файлы всех четырёх позиций и связанный кэш relay. Ссылки оставшихся
карточек защищают общие файлы и кэш. Очередь переживает сбои и отмечается выполненной
после удаления. Сохраняются только служебные ID/даты, а обработанные ключи кэша очищаются.

На сборщике `cleanup_collector_photos.py` удаляет старые локальные копии только для
явных `is_active=0`; записи SQLite не удаляет. Шаг включён в `pull_db.sh` после импорта.
Новый поток фото работает напрямую между серверами и не создаёт архив на сборщике.

Перед установкой: применить `scripts/migrations/20261123_remove_sold_cars.sql`,
разместить `sold_cars.py`, оба скрипта очистки и обновлённые import/pull, установить
и включить unit/timer. Импорт и очистка запускаются вручную только после проверки
источника. Без `--apply` файловые скрипты показывают план и ничего не удаляют.

Первая очистка: 25 970 записей сайта, 4 213 файлов сайта и 6 582 старых файла
сборщика; без ошибок. Файлы освободили примерно 0,7 ГБ суммарно на двух серверах.
Резервная копия таблицы и старых скриптов перед изменением:
`/srv/che168/backups/sold-purge-20261123T142700Z` на сервере сайта.
Файлы фото в резервную копию не дублировались. PostgreSQL может использовать
освободившиеся страницы таблицы повторно без немедленного уменьшения файла БД.
