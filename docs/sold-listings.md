# Удаление снятых с продажи и слишком старых автомобилей

По решению владельца снятые объявления и их фото больше не храним на сайте.
Основание — явное `is_active=0` в проверенной копии базы сборщика. Отсутствие
строки, таймаут, ошибка сети, пустая цена или неизвестный статус не означают продажу.

При импорте копируются только активные записи. Для подтверждённых неактивных ID
в одной транзакции создаётся очередь `sold_car_cleanup` и удаляются строки `cars`.
Повторный импорт не возвращает их. Сборщик сохраняет исходную отметку снятия;
если источник действительно выставит объявление снова, активная запись может
вернуться обычным импортом.

Дата растаможки для отбора равна текущей дате PostgreSQL плюс 45 дней. Если
первый день месяца регистрации совпадает с пятилетней границей или раньше неё,
активная строка из снимка пропускается. Для отсутствующей или нераспознанной даты
используется 1 июля года регистрации. Данные с неизвестным месяцем и годом нельзя
классифицировать по возрасту. Слишком молодые машины импортируются как обычно.
Если свежий снимок уточнил дату, импорт учитывает её до удаления.

Слишком старые карточки PostgreSQL удаляются в той же транзакции через
`sold_car_cleanup`. Совпадения по возрасту обрабатываются отдельно от проданных,
даже если предохранитель пропустил удаление последних. Журнал выводит число
удалённых по возрасту отдельной строкой. Для оценки до записи есть
`sudo -u postgres python3 /opt/avtopodborimport/import_cars.py --dry-run`.

Перед удалением импорт сверяет снятые ID с машинами, которые есть в базе сайта.
Если совпадений больше 300 и одновременно больше 5% активных машин до импорта,
предохранитель пропускает удаление. Импорт сохраняет новые данные и возвращает
код `3`. В журнал попадают количество кандидатов, число активных машин и порог.
`SOLD_DELETE_MAX_PERCENT` меняет долю, а нижний предел порога остаётся 300 машин.
Удаление по возрасту использует отдельный порог `AGED_DELETE_MAX_PERCENT`.
По умолчанию это 10% активных машин сайта до удаления, с округлением вниз.
При превышении порога возрастные строки остаются в базе, импорт возвращает
код 3. Журнал содержит число кандидатов, порог и дату границы. Допустимые
значения обеих настроек — от 0 до 100.

Для проверенного вручную удаления запустить `import_cars.py --allow-mass-delete`.
Флаг снимает оба порога и позволяет повторно обработать текущий снимок.

## Оповещения об импорте

После ненулевого кода импорта `pull_db.sh` запускает `notify.py`. При коде 3
уведомление содержит число кандидатов, порог и команду для подтверждённого
вручную повтора. Для возрастного предохранителя есть отдельный текст с датой
границы. Если сработали оба порога, сведения об обоих входят в одно сообщение.
Без конфигурации уведомление пишется в `/srv/che168/pull.log`.

Для Telegram создайте на сервере сайта отдельный файл
`/etc/avtopodbor-alerts.env` с владельцем `root` и правами `600`. Заполните
значения на сервере в формате `ИМЯ=значение` без кавычек.

```dotenv
ALERT_TELEGRAM_BOT_TOKEN=<токен бота>
ALERT_TELEGRAM_CHAT_ID=<ID чата>
```

Отметка в `/srv/che168/import-alerts.state` записывается перед отправкой. Один
снимок даёт не более одной попытки и при сетевом сбое. В журнал пишется итог
отправки без токена. [Telegram Bot API](https://core.telegram.org/bots/api#sendmessage)

## Очередь очистки фотографий

`avto-sold-cleanup.timer` каждые 15 минут повторяет очистку файлов сайта. Этот же
шаг выполняется после каждого импорта снимка, завершившегося кодом `0` (дважды в сутки). Очистка согласована с блокировками
импорта и загрузчика: во время партии переносится на следующую попытку. Удаляются
локальные файлы всех четырёх позиций и связанный кэш relay. Ссылки оставшихся
карточек защищают общие файлы и кэш. Очередь переживает сбои и отмечается выполненной
после удаления. Сохраняются только служебные ID/даты, а обработанные ключи кэша очищаются.

На сборщике `cleanup_collector_photos.py` удаляет старые локальные копии только для
явных `is_active=0`; записи SQLite не удаляет. Шаг включён в `pull_db.sh` после импорта.
Новый поток фото работает напрямую между серверами и не создаёт архив на сборщике.

Перед установкой: применить `scripts/migrations/20261123_remove_sold_cars.sql`,
разместить `sold_cars.py`, оба скрипта очистки и обновлённые import/pull, установить
и включить unit/timer. Импорт и очистка запускаются вручную только после проверки
источника. Без `--apply` файловые скрипты показывают план и ничего не удаляют.

Первая очистка: 25 970 записей сайта, 4 213 файлов сайта и 6 582 старых файла
сборщика; без ошибок. Файлы освободили примерно 0,7 ГБ суммарно на двух серверах.
Резервная копия таблицы и старых скриптов перед изменением:
`/srv/che168/backups/sold-purge-20261123T142700Z` на сервере сайта.
Файлы фото в резервную копию не дублировались. PostgreSQL может использовать
освободившиеся страницы таблицы повторно без немедленного уменьшения файла БД.

## Резерв первого удаления по возрасту

Резерв PR №68 находится на сервере сайта в
`/opt/avtopodborimport/config-backups/aged-listings.ptDRX1SH`. По замеру
26.11.2026 каталог занимает 2 278 051 840 байт, около 2,12 ГиБ.
В нём сохранены строки PostgreSQL и жёсткие ссылки на фото и кэш.

Разовое напоминание в Codex назначено на 3 декабря 2026 года, 22:40 МСК.
Удаление резерва допустимо после этого срока и при отсутствии жалоб на
пропавшие машины. При жалобах копию следует сохранить до выяснения.
