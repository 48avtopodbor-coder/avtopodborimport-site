# Единый процесс каталога

1. Сборщик сохраняет оригинал и структурированные данные. Проверенный снимок импортируется одной транзакцией.
2. `brand_aliases` и `model_aliases` сопоставляют марку и модель; `city_translations` переводит город. Исходные поля не изменяются. Сопоставления общие для всех объявлений и будущих импортов.
3. После импорта `refresh_catalog_queue.py` собирает неизвестные марки, модели и города. Очередь считает только активные машины с ценой, сохраняет историю и количество затронутых карточек. Повторный запуск не дублирует работу.
4. Описания хранятся отдельно по точному исходному тексту и MD5. Словарь обрабатывается после ночного импорта и каждый час. Новые неизвестные тексты требуют перевода. `sync_seller_translations.py` выполняет полный цикл через Codex CLI на доверенном рабочем компьютере: экспорт → перевод → отдельная сверка → очистка оставшихся иероглифов → импорт проверенного результата. На сервер не переносятся учётные данные Codex. Команда возобновляема, требует включённого компьютера и авторизованного CLI. Постоянный облачный переводчик пока не подключён.
5. Проверенные термины принимаются `apply_catalog_translations.py reviewed.json --apply`. Формат: `entries`, у каждой записи `kind` (`brand/model/city`), `brand` (slug марки для модели), `source`, `name`, `slug` (для марки/модели), `reviewed: true`, необязательный `source_url`. Скрипт обновляет справочники, существующие заголовки и очередь. Для нового города `resolve_city_routes.py` получает координаты города в КНР и дорожный маршрут OSRM. Результат сверяется по провинции, затем `apply_city_routes.py routes.json --apply` сохраняет недостающую оценку и источник. Одноимённые посёлки исключаются. Для Хунхэ используется административный центр Мэнцзы. Новые оценки обозначены ≈ и сопровождаются атрибуцией OpenStreetMap.
6. Сайт читает сохранённые результаты. `catalog_translation_health` показывает пропуски по категориям. Пустое исходное описание не считается переводимым текстом.

## Фото

`avto-photo-relay.service` слушает только 127.0.0.1:3011. Nginx направляет точный `/api/img` по шаблону `scripts/deploy/photo-relay.nginx.conf`. URL проверяется, разрешён только HTTPS autoimg.cn. Через существующий SSH alias hosting источник загружается на стороне сборщика. Передача не меняет байты и разрешение. Кэш по SHA256 полного URL в `/opt/avtopodborimport/photo-cache`; одновременно максимум два запроса к источнику. Новые файлы не сохраняются, если осталось менее 4 GiB. Ошибка источника возвращается как ошибка, а не кешируется как изображение. Фоновый загрузчик отдаёт приоритет главным фотографиям всех автомобилей, затем вторым и третьим.

## Установка

Сохранить резервную копию PostgreSQL. Применить `20261123_translation_queue.sql`, затем установить новые Python-скрипты и `run_translation_worker.sh` в `/opt/avtopodborimport/`. Применить проверенный файл терминов; выполнить импорт с `--force` и проверить health view. Для фото установить unit, проверить загрузку на 3011, добавить location в HTTPS server, проверить `nginx -t` и reload. Для отката фото удалить только этот location и выполнить reload; Next.js вернёт старый proxy. Справочники остаются совместимы с предыдущей версией сайта.
