# Сборщик каталога Che168

Здесь хранятся исходники с рабочего сервера сборщика на 26 ноября 2026 года.

- `run_hourly.sh` запускает `hourly_job.sh` под общей блокировкой и пишет журнал. `run_daily.sh` содержит отдельный сценарий полного прохода.
- `scraper.py` собирает объявления и обновляет цены. `details.py` добавляет характеристики, описания и ссылки на фотографии. `enrich.py` проверяет, доступны ли объявления.
- `database.py` описывает схему SQLite и операции записи. `backup.sh` создаёт согласованную копию базы. `show.py` показывает статистику.
- `config.example.py` содержит рабочий список марок, возрастной фильтр и другие параметры без секретов. Для локальной проверки SQLite скопируйте шаблон в `config.py`.

Сетевой обход использует установленный на сервере модуль `che168_api.py` и локальный `config.py`. Эти рабочие файлы и каталог `data/` хранятся на сервере. Скрипты расписания используют серверные пути и окружение `.venv`.

## Повторная загрузка неполных характеристик

Полный кэш комплектации используется только при наличии топлива, привода и мощности.
Ответ, содержащий только регистрацию или рекомендованную цену, не записывается
как техническая комплектация. Продающиеся машины с отсутствующими основными
характеристиками возвращаются в обычную очередь через семь дней после попытки.
Существующий `params_at` хранит время попытки; отдельное расписание не требуется.
Паузы API и общий `data/.lock` сохраняются.

Объём двигателя читается сначала из `排量(mL)`, затем из `排量(L)` с переводом литров
в миллилитры. Из рекламного обозначения двигателя объём не выводится. У электрических
машин отсутствие объёма двигателя нормально.

`backfill_engine_volumes.py` восстанавливает отсутствующий объём из сохранённого
`params_json`, без запросов к API. Сначала запустить без параметров для проверки,
затем под тем же замком с `--apply`. Уже заполненные значения не перезаписываются;
повторный запуск безопасен.

Установка: под существующим `data/.lock` сохранить резервную копию `details.py`
и SQLite, проверить синтаксис новым Python, заменить файл и запустить обычный
`details.py --minutes 40`. Не запускать второй обход одновременно с `hourly_job.sh`.
После успешного завершения перенести проверенный снимок прежним `pull_db.sh`.
Для отката вернуть предыдущий скрипт; новые заполненные поля совместимы с ним.

Проверки: `python3 -m unittest discover -s tests -p test_details_recovery.py -v`.
